# si - CLI tool for SiebenApp goal management

## Overview

`si` is a command-line interface (CLI) tool for managing goals within SiebenApp.
It provides full control over goal creation, viewing, modification, and dependency management.
The tool is designed to complement SiebenApp's graphical interface, offering a powerful way to work with projects through the terminal.

## Key Features

- **Goal Creation & Management**: Easily create, rename, delete, and organize goals.
- **Dependency Handling**: Define relationships between goals (parent-child, blocking, or related).
- **Efficient Workflow**: Ideal for users who prefer command-line interfaces or need to manage goals in scripts.
- **Agent-friendly**: Agents have full access to the goal database and may use it both for reading and modifying it.

## Usage

### Basic Commands

All commands follow this pattern:

```bash
si <database-file> <command> [options]
```

Some arguments may be long enough and contain multiple words (like goal descriptions).
Always wrap them into quote symbols if you want them to be processed properly.

#### Create a New Goal
```bash
si <database-file> new <goal-name>
```
Creates a new goal file with the specified goal.
Returns an error if the file already exists.

#### View Goals
```bash
si <database-file> view
```
Show a goal list from the given file.
Goal output includes the following information:
* Goal id: unique number that's assigned to it when a goal is created.
  Many edit commands require to provide one or more goal ids.
  That's why it's always possible to view id of any goal.
* Goal closeable status: "switchable" or "not switchable".
  A goal could only be closed when it has no subgoals or blockers.
  If it has any of such dependencies, all of them must be closed beforehand.
* Goal description: a text user previously entered to describe the goal.
* Goal metadata: list of subgoals (if any), blockers and related goals.
* Goal labels: optional set of labels associated with the given goal by engine.

By default, only open goals are shown.
Use additional options to customize the display:
- `-n`: Show not only open, but also closed goals.
- `-z <goal-id>`: "Zoom into" given goal.
   In other words, only show its subgoals and directly related goals.
- `-t`: Show only "top", or "switchable", or "actionable" goals.
  Only they could be completed to the moment.
- `-f <filter>`: Filter goals by a provided phrase.

#### Add Subgoals
```bash
si <database-file> add <goal-id> <goal-name>
```
Adds a sub-goal to given goal.
Sub-goals automatically block their parent goals.

#### Insert Goals
```bash
si <database-file> insert <parent> <child> <goal-name>
```
Inserts a new intermediate goal between already existing parent and child goals.
Will return error if a new goal relation may create a loop.

#### Link Goals
```bash
si <database-file> link <first> <second> [--parent|--block|--relate]
```
Creates relationships between goals:
- `--parent`: Links goals as parent-child (default behavior).
- `--block`: Blocks goal <first> with a goal <second>.
- `--relate`: Creates a non-blocking relationship between <first> and <second>.
  Such links will not prevent <first> goal from being closed when <second> is open yet.

There may be only one relation between two goals a time.
Creation of a link with another type than existing one will just change a type of this relation.
Every goal may have only one parent, thus creation of a parent-child link will transform previous parent link for "child" goal into a non-blocking relation.
Will return error if a link of given type between goals already exists.

#### Unlink Goals
```bash
si <database-file> unlink <first> <second>
```
Removes any defined relationships between goals.
Will return error if a link doesn't exist.

#### Rename Goals
```bash
si <database-file> rename <goal-id> <goal-name>
```
Changes the name of provided goal.

#### Auto-link Goals
```bash
si <database-file> autolink <goal-id> <marker>
```
Automatically parents new or renamed goals to the given one, based on keywords (e.g., "time:" might link to a time-tracking goal).

#### Close/Open Goals
```bash
si <database-file> close <goal-id>
si <database-file> open <goal-id>
```
Marks goals as closed or reopens them.

#### Delete Goals
```bash
si <database-file> delete <goal-id>
```
Permanently deletes a goal (no confirmation prompt).
All children sub-goals and their relations are deleted too.
Goal deletion is not encouraged to use as a part of regular workflow because it cannot be undone.
In general, it will be enough simply to close a goal, and it will go away from default view.
To fix goal name, you could use `rename` command, to fix its parent, there's `link` command.
Try to delete only goals that were created by a mistake and have no meaning at all.

## Best Practices

- Use separate database files (`*.db`) for different projects to keep goals organized.
- Use filtering options (`-f` and `-z`) to quickly locate goals in large databases.
